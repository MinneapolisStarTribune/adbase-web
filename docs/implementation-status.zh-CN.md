## 测试数据

元数据位于 `src/modules/forecasting/infrastructure/metadata.json`，包括 3 个年度、3 个区域、3 个产品及 4 类账号。`mock-repository.ts` 生成 37 个广告主和 37 条预测记录，覆盖 30 条分页边界、零金额、负金额、小数、特殊广告主 999999、带逗号／引号／换行及公式前缀的产品名称。

模拟规则及权限矩阵见 [Synthetic Forecasting Contract](mock-contract.en.md)。这些规则使功能可运行，不代表已确认存储过程实际行为。

## 已通过的检查

- TypeScript 类型检查、ESLint、Prettier。
- 27 个单元／业务测试：元数据关联、角色与区域范围、搜索优先级、分页及总额、金额校验、创建与编辑、重复与并发冲突、广告主变更约束、CSV、会话过期和配置隔离。
- 5 个 Chromium 端到端场景：普通用户查询及编辑／取消／退出；代理用户新增预测；管理员维护广告主并下载 CSV；无区域账号拒绝访问；直接 HTTP 调用验证认证、授权、Origin 和会话撤销。
- Next.js 优化构建。
- `docker compose config --quiet` 配置校验。

测试在 Windows、Node.js 20.19.5 上运行；CI 和 Docker 定义使用 Node.js 24。浏览器测试独立启动并停止 `127.0.0.1:3101` 的模拟服务，不使用现有业务页面。

补充回归：修复未配置 `APP_ORIGIN` 时 `localhost` 与 Next.js 内部 `127.0.0.1` 地址不一致导致的登录 403。校验现使用请求 Host，显式配置的来源仍严格匹配，且不信任转发头。修复后通过 40 个单元／业务测试和 6 个端到端场景，包含 `localhost` 登录与退出、IP 地址访问以及跨站请求拒绝；类型检查、规范检查和构建也通过。
